# VRM Gesture — распознавание и анимация жестов через веб-камеру

Приложение для работы с русским жестовым языком (РЖЯ) и дактилем в браузере. VRM-аватар повторяет движения пользователя через веб-камеру, распознаёт жесты в текст, обучается новым жестам на лету и переводит напечатанный текст обратно в анимацию жестов.

Всё работает локально в браузере. Никаких серверов, никаких облаков — только MediaPipe в WebAssembly и Three.js на WebGL.

---

## Запуск

```bash
npm install
npm run dev
```

Открыть http://localhost:5173 — приложение откроется сразу, работает в последних Chrome/Firefox/Safari.

Для продакшен-сборки:

```bash
npm run build
```

## Четыре вкладки

Приложение разбито на четыре независимых режима. Они переключаются вверху левой панели.

### 1. Интерактив

Основной рабочий режим. Слева селектор модели аватара и сцены, справа панель распознавателей.

В правой панели пять подрежимов:

- **Жесты** — распознавание готовых жестов РЖЯ по форме руки. Словарь зашит в `src/utils/gestureRecognizer.js`, расширяется правилами. Удержание формы 800 мс подтверждает жест, он добавляется в строку распознанных слов.
- **Дактиль** — то же самое, но для букв русской дактильной азбуки. Каждая буква = одна поза руки. Включены 26 статических букв.
- **Обучи** — запись пользовательских эталонов для DTW-распознавателя. Вводится метка (ПРИВЕТ, Й, СПАСИБО), нажимается REC, после отсчёта 3-2-1 показывается жест за 2 секунды. После успешной записи предлагается сохранить жест как анимацию — это сделает его доступным во вкладке «Перевод».
- **Запись** — запись полноценной анимации аватара (поза + обе руки + лицо + тело). Сохраняется в браузерном хранилище, проигрывается во вкладке «Анимации» или по запросу в «Переводе».
- **Датасет** — сбор размеченных сэмплов для исследований. Нажимается буква, записывается 500 мс, экспортируется JSONL.

Аватар в этом режиме живой — повторяет движения пользователя через MediaPipe и Kalidokit.

### 2. Зеркало

Простейший режим. Включаешь камеру — аватар зеркалит твои движения в реальном времени. Никакого распознавания, никакого сохранения. Используется чтобы проверить трекинг, подобрать ракурс/освещение или просто «примерить» аватар на себя.

### 3. Анимации

Плеер сохранённых анимаций. В списке показаны все записи, созданные во вкладках «Запись» и «Обучи» (если там согласились сохранить эталон как анимацию). Кликом выбирается запись, кнопка «Запустить» воспроизводит её на аватаре.

Аватар в этом режиме в T-позе — камера выключена, вся поза задаётся кадрами из записи.

### 4. Перевод

Два подрежима:

**Из текста** — пишешь «ПРИВЕТ СПАСИБО» в поле, нажимаешь «Перевести», аватар последовательно проигрывает записанные анимации для каждого слова. Между словами короткая пауза на возврат в T-позу. Если слова нет в базе — оно отмечается «(нет)» в очереди и пропускается.

**Распознать жест** — обратное направление. Включаешь камеру, показываешь жест — DTW-распознаватель находит ближайший эталон, и если к этому эталону есть записанная анимация, аватар её проигрывает. Над сценой появляется большой баннер «Распознано — ПРИВЕТ», который сменяется на «Воспроизвожу — ПРИВЕТ» во время анимации.

В этом режиме аватар **не повторяет** живую руку пользователя. Камера используется только для распознавания, аватар стоит в T-позе пока не совпадёт жест.

## Полный цикл работы

```
[Интерактив → Обучи] записал «ПРИВЕТ»
        ↓
         согласился «сохранить как анимацию»
        ↓
[Перевод → Из текста] печатает «ПРИВЕТ» → аватар проигрывает
        ↓
[Перевод → Распознать] показал «ПРИВЕТ» камере → аватар проигрывает
```

Одна запись работает в обе стороны: и для текст→жест, и для жест→жест.

## Как устроен трекинг и аватар

Пайплайн камера → аватар:

```
Web-камера → MediaPipe Holistic → landmarks (поза + руки + лицо)
        ↓
Kalidokit (Pose.solve, Hand.solve, Face.solve) → углы для VRM humanoid-костей
        ↓
VRMAvatar.useFrame → slerp по каждой кости
        ↓
Three.js → WebGL-рендер
```

MediaPipe Holistic даёт 33 точки позы, по 21 точке на каждую руку, и 468 точек лица. Работает в браузере на WebAssembly, отдаёт ~25-30 FPS на среднем ноутбуке.

Kalidokit разгадывает эти плоские landmarks в углы — именно так они и пишутся потом в кости VRM. VRM-скелет стандартизирован: любая корректная VRM-модель (из VRoid Studio, Booth, VRoid Hub) имеет одинаковые имена костей, поэтому трекинг работает на любом аватаре без переделки кода.

Slerp-интерполяция с коэффициентом 0.3-0.5 на кадр сглаживает дрожание MediaPipe и делает движения более естественными.

## Как устроено распознавание

Три независимых алгоритма решают разные задачи.

### Статическое распознавание (жесты + дактиль)

Файл `src/utils/gestureRecognizer.js`. Правила на углах суставов и относительных позициях пальцев. Для каждого жеста проверка «мизинец согнут И указательный выпрямлен И большой палец сверху» и т. п. Нужно удерживать форму 800 мс для подтверждения.

Работает для 26 статических букв дактиля и словаря жестов. Не работает для динамических букв (Й, Р, Ц, Ч, Щ, Ы, Ь, Ъ) — у них движение в середине жеста, для этого нужен другой подход.

### DTW-распознавание (динамические жесты)

Файлы `src/utils/templateMatcher.js`, `src/utils/keyframeExtractor.js`.

Идея: пользователь записывает эталоны каждого жеста, и в рантайме мы сравниваем «окно последних 2 секунд кадров» с каждым эталоном через Dynamic Time Warping. DTW умеет выравнивать две последовательности разной длины и скорости — это классический алгоритм из распознавания речи, хорошо подходит для жестов.

Перед матчингом каждая последовательность сжимается через экстремумы Δ(t): из 60 кадров остаётся 6-10 «ключевых» кадров в моменты локальных минимумов изменения формы руки. Это даёт ~10× ускорение DTW и подавление шума.

Порог матчинга 0.45 (DTW-дистанция на нормализованную длину). Работает из коробки с 2-3 записями на класс. Точность растёт с каждой дополнительной записью — чем разнообразнее эталоны, тем надёжнее матчинг.

### Запись и воспроизведение анимаций

Файл `src/hooks/useGestureRecorder.js`. Store zustand хранит массив записей в localStorage. Каждая запись — массив кадров MediaPipe results (поза, обе руки, лицо) с временными метками.

Воспроизведение в `AnimationPlayer.jsx` и `TranslateMode.jsx` идёт через тот же `resultsCallback`, что использует живая камера — но кадры берутся из записи. Аватар получает их через обычный пайплайн Kalidokit → VRM и проигрывает.

## Архитектурные решения

### Два параллельных callback'а для MediaPipe

В `useVideoRecognition` (zustand-store) два слота:

- `resultsCallback` — пишет в аватар (этот callback регистрирует `VRMAvatar`).
- `gestureCallback` — пишет в активный распознаватель (GestureTranslator, TemplateMode, RecognizeGesturePanel).

`CameraWidget` вызывает оба на каждом кадре MediaPipe. Это позволяет распознавателю и аватару работать независимо, не мешая друг другу.

### Флаг liveFeedBlocked

В режиме «Перевод → Распознать жест» аватар должен быть в T-позе, пока DTW не сматчит жест — и только потом проиграть записанную анимацию. Но MediaPipe всё равно будет слать живые кадры.

Решение: в store есть флаг `liveFeedBlocked`. Когда он поднят, `CameraWidget` **не вызывает** `resultsCallback` для аватара (то есть живая рука физически до аватара не доходит). При этом `gestureCallback` продолжает вызываться — распознаватель слушает как ни в чём не бывало.

Проигрывание записи в этом режиме идёт через прямой вызов сохранённой ссылки на callback аватара (`avatarCbRef`), минуя флаг.

### Переиспользование инстансов MediaPipe

MediaPipe Holistic инициализируется ~2-3 секунды (загрузка wasm + моделей). Чтобы повторное включение камеры было мгновенным, в `CameraWidget` инстансы `Holistic` и `Camera` держатся в ref'ах — `stop()/start()` переключают видеопоток, а модели остаются загруженными.

- `analyzer.html` — отдельная HTML-страница (открывается двойным кликом, без сборки) для визуализации CSV-логов траекторий жестов. Показывает Δ(t), находит локальные минимумы как ключевые кадры, разделяет поток на HOLD/MOVE сегменты.

## Известные ограничения

- Трекинг одной фронтальной камерой плоский — глубина (координата Z) у MediaPipe оценивается эвристически, поэтому жесты, где рука уходит вперёд/назад, распознаются хуже.
- DTW-распознаватель работает на сжатой форме руки (20 точек × 2 координаты = 40-мерный вектор на кадр). Это даёт инвариантность к положению и масштабу, но не к ориентации запястья — если эталон записан с рукой ладонью к камере, а показываете с рукой боком, матч может не сработать. Решение: записывать несколько вариантов одного жеста.
- Динамические буквы русского дактиля (Й, Р, Ц, Ч, Щ, Ы, Ь, Ъ) правилами не распознаются, только через DTW после записи эталона в «Обучи».
- VRM-модели от разных авторов могут требовать разной ориентации (flip на 180°). Кнопка ⟲ рядом с селектом модели переключает это в рантайме.
